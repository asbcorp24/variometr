# Прототип вариометра ESP32

Интерфейс дисплея на русском: вариометр, компас, диагностика, настройки и тест
пищалки. Кириллица выводится встроенным растровым шрифтом 5×7, надписи — прописными
буквами. Поддерживается UTF-8, включая Ё; ширина текста считается по символам.
На компасе С/В/Ю/З означают север/восток/юг/запад. Команды Serial остаются прежними.

Основной режим: высота по QNH, относительная высота, вертикальная скорость,
усреднитель и звуковая индикация. Четыре кнопки управляют экранами и настройками.
Диагностика доступна через Serial, 115200 бод,
и отдельный экран ILI9341 (команда `v`).
Платформа закреплена на espressif32 6.10.0 (Arduino ESP32 2.x), совместимой с
установленным PlatformIO Core 6.1.19. Подвижная ссылка pioarduino stable требовала Core >=6.2.0.
Прошивка не является готовым полётным прибором. Время RTC и EEPROM не перезаписываются.

## Первый запуск рабочего режима

Загрузить прошивку, открыть монитор на 115200 и нажать EN. После первого валидного
измерения нужно примерно 1,5 секунды для набора окна фильтра: WARMUP сменится на READY.
Оставить прибор неподвижным на 10–15 секунд, проверить скорость около нуля.
Отправить `z` для обнуления относительной высоты, затем `m` для включения звука.
Поднять прибор плавно на 1–2 метра и подержать неподвижно: скорость сначала должна
стать положительной, затем вернуться к нулю. После опускания ожидается отрицательная
скорость. Из-за фильтрации реакция задерживается примерно на 1–2 секунды;
быстрый взмах не подходит для оценки точности.

QNH по умолчанию 1013,25 гПа — это стандартная опора, не автоматически определённое
местное давление. Для высоты над уровнем моря установить актуальное QNH командой
`q1018.5` и Enter (пример числа, не рекомендация для текущего места). Давление,
измеренное самим датчиком на высоте, нельзя просто использовать как QNH.
Относительная высота автоматически отсчитывается от первого измерения после запуска;
команда `z` переносит ноль на текущую отфильтрованную высоту.

QNH и период усреднения сохраняются во flash при изменении и восстанавливаются
после перезапуска. Если запись не удалась, Serial сообщает RAM only. Относительный
ноль не сохраняется. После каждого включения звук выключен; `m` включает его,
`x` немедленно выключает. Автораспознавания взлёта на этом этапе нет.

## Измерение и звук

Бародатчик читается с целевой частотой 10 Гц, экран обновляется 5 раз/с. Настройки
BMP280: температура ×2, давление ×16, аппаратный фильтр выключен. Высота вычисляется
по барометрической формуле, затем сглаживается с постоянной времени 0,35 с.
Скорость — наклон прямой по последним 16 измерениям высоты с учётом реального времени,
дополнительно сглаженный с постоянной времени 0,3 с. AVG — среднее скоростей за
последние N секунд, по умолчанию 10, настройка `a1`…`a30` и Enter. Пока окно
усреднения не заполнено, используется имеющаяся часть. BMI160 пока не участвует
в расчёте вертикальной скорости.

Звук управляется текущей отфильтрованной скоростью, не AVG:

- Подъём: включается от +0,2 м/с, выключается при +0,1 м/с и ниже. Частота 800–1800 Гц,
  период писка уменьшается с ростом скорости, длительность писка равна половине периода.
- Снижение: от −2 м/с постоянный тон 350 Гц, выключение при скорости не ниже −1,8 м/с.
- Опасное снижение: от −10 м/с чередование 700/1800 Гц, выход из сирены при −9,5 м/с
  и выше; после этого может продолжиться обычный сигнал снижения.

Зона тишины около нуля и пороги возврата выбраны для подавления дребезга из-за шума.
Это параметры первого прототипа, а не окончательно согласованные звуковые кривые ТЗ.
Громкость фиксирована; шесть уровней пока не реализованы.

При ошибке давления, потере датчика или разрыве измерений более 0,5 с скорость
сбрасывается и звук блокируется до набора нового окна. Смена QNH также сбрасывает
фильтр, чтобы не создавать ложный набор высоты. `s`, `d` и `b` сбрасывают фильтр;
`b` дополнительно выключает рабочий звук. Пропавший датчик после восстановления
соединения можно повторно инициализировать командой `d`.

Пока не реализованы журнал и таймер полётов, определение взлёта/посадки, калибровка
компаса и компенсация наклона, TouchScreen и установка RTC.
Подписи экранов пока английские. Новые функции требуют проверки на реальной плате.

## Подключение

Отключить USB перед изменением проводов. Для первого теста питание ESP32 от USB,
питание модулей от 3V3, общая земля. Не подтягивать SDA/SCL к 5 В.

| Модуль | Вывод | ESP32 |
|---|---|---|
| RTC HW-084, предположительно DS3231 | VCC / GND | 3V3 / GND |
| RTC | SDA / SCL | GPIO21 / GPIO22 |
| GY-BMI160 | VCC / GND | 3V3 / GND |
| GY-BMI160 | SDA / SCL | GPIO21 / GPIO22 |
| GY-BMI160 | SDO (SA0) / CS (CSB) | 3V3 / 3V3 |
| GY-273 с QMC5883L или HMC5883L | VCC / GND | 3V3 / GND |
| GY-273 с QMC5883L или HMC5883L | SDA / SCL | GPIO16 / GPIO17 |
| BMP280/BME280, модуль с поддержкой 3,3 В | VCC / GND | 3V3 / GND |
| BMP280/BME280 | SDA / SCL | GPIO21 / GPIO22 |
| Keyestudio buzzer | G / V / S | GND / 3V3 / GPIO14 |

У бародатчика, если выведены CS/CSB и SDO: CS/CSB подключить к 3V3 для I²C,
SDO к GND для адреса 0x76 (или 3V3 для 0x77). Ориентироваться на подписи конкретной платы.
У BMI160 INT1/INT2 и выводы вспомогательного интерфейса оставить неподключёнными.
MPU для этого этапа отключить. Если SDO на модуле жёстко соединён с землёй,
не замыкать его на 3V3: сначала проверить схему/перемычку конкретного модуля.
У RTC SQW и 32K не подключать. Подключение TFT описано ниже, SD пока не используется.
У магнитометра вывод DRDY (если имеется) не подключать. Магнитометр подключается
к отдельной второй шине I²C: SDA=GPIO16, SCL=GPIO17. Снять его старые соединения
с GPIO21/22; две шины между собой не соединять. RTC, BMI160 и BMP280 остаются на GPIO21/22.
GPIO16/17 теперь заняты магнитометром: прежний предварительный резерв под кнопки
«Вниз» и «ОК» отменён; эти кнопки перенесены на GPIO34/35.
Если на модуле нет подтяжек SDA/SCL, добавить по резистору 4,7 кОм от каждой
линии второй шины к 3V3. Подтяжки первой шины для второй не действуют.
Для проверки держать модуль вдали от магнитов, стали, баззера и силовых проводов.

**BMI160 SDO/SA0 подключить к 3V3:** RTC использует 0x68, BMI160 должен быть на 0x69.
CS/CSB должен быть на 3V3 уже при включении питания для выбора I²C.
Прошивка не настраивает BMI160 по адресу 0x68, чтобы не записать его настройки в RTC.
На RTC возможна цепь подзарядки батареи: перед использованием обычной CR2032
нужно проверить/отключить эту цепь. Первый тест можно выполнить без резервной батареи.

## Монитор батареи MAX17048

Поддержка подготовлена до установки модуля. На всех рабочих страницах и в меню
справа вверху отображаются батарея и процент. Если MAX17048 ещё не найден,
показание фиксировано на **100%**, с пометкой **ДЕМО**; напряжение не выдумывается.
После обнаружения совместимого устройства на 0x36 показания автоматически
переходят на измеренные процент и напряжение. Опрос — раз в секунду, поиск
отсутствующего модуля — раз в 5 секунд. Перепрошивка после установки не нужна.

Подключение модуля **Adafruit MAX17048** к имеющейся шине:

| MAX17048 | Подключить |
|---|---|
| SDA / SDI | GPIO21, параллельно SDA барометра и RTC |
| SCL | GPIO22, параллельно SCL барометра и RTC |
| GND | Общая земля ESP32 |
| VIN | 3V3 ESP32 — питание логической части модуля Adafruit |
| Разъём BAT / JST | Одна Li-ion/LiPo ячейка 3,7 В номинально, до 4,2 В; проверить полярность |
| INT, QStart | Не подключать |

У Adafruit сам MAX17048 питается от аккумулятора: без него устройство может
не отвечать. BAT — линия аккумулятора, её не соединять с 3V3 ESP32.
Для платы другого производителя использовать её схему: выводы VIN/VCC/BAT
могут отличаться. Монитор измеряет батарею, не заменяет зарядник или стабилизатор
питания ESP32. [Схема подключения и выводы Adafruit](https://learn.adafruit.com/adafruit-max17048-lipoly-liion-fuel-gauge-and-battery-monitor/pinouts).

Драйвер проверяет регистр версии и читает VCELL/SOC с контролем результата I²C;
сброс, quick-start и запись конфигурации не выполняются. При сбое чтения или
неподдерживаемом ответе — **--% / ОШИБКА**. После успешного обнаружения потеря
связи не возвращает демонстрационные 100% до перезапуска. Проверка свежести — 3 с.
Преобразование регистров соответствует [реализации Adafruit](https://github.com/adafruit/Adafruit_MAX1704X/blob/main/Adafruit_MAX1704X.cpp).
Физического модуля пока нет: проверены сборка и программные сценарии.

## Четыре кнопки

Использовать нормально разомкнутые кнопки без фиксации. Каждая кнопка замыкает
свой GPIO на GND. Не подключать кнопки к 5 В. Проводку менять при отключённом USB.

| Кнопка | GPIO | Подтяжка |
|---|---|---|
| Экран / Назад | GPIO32 | Внутренняя, включена в прошивке |
| Вверх / + | GPIO33 | Внутренняя, включена в прошивке |
| Вниз / − | GPIO34 | Внешний резистор 10 кОм к 3V3 обязателен |
| ОК | GPIO35 | Внешний резистор 10 кОм к 3V3 обязателен |

Для каждой из двух кнопок GPIO34/35 схема отдельная:

```text
3V3 ----[10 кОм]----+---- GPIO34 (или GPIO35)
                   |
                 кнопка
                   |
                  GND
```

GPIO34/35 работают только на вход и не имеют внутренних подтяжек. Даже если сами
кнопки ещё не установлены, резисторы нужны для определённого уровня на этих входах;
иначе возможны ложные нажатия. Кнопки на GPIO16/17 не подключать — там магнитометр.
У четырёхконтактной тактовой кнопки выбрать контакты, которые соединяются именно
при нажатии; два вывода с одной стороны могут быть соединены постоянно.

| Кнопка | Короткое нажатие | Удержание от 0,8 с |
|---|---|---|
| Экран / Назад | Вариометр → компас → диагностика; в меню выйти или отменить правку | Включить/выключить звук; в тесте пищалки — остановить тест |
| Вверх / + | Предыдущий пункт; увеличить редактируемое значение | Повторять действие каждые 120 мс |
| Вниз / − | Следующий пункт; уменьшить редактируемое значение | Повторять действие каждые 120 мс |
| ОК | Открыть настройки, выбрать пункт или подтвердить | Открыть настройки с основного экрана/диагностики |

Короткое действие срабатывает при отпускании. После долгого нажатия короткое не
выполняется. Дребезг подавляется интервалом 30 мс. Зажатая при запуске кнопка
игнорируется до первого отпускания. Одновременные сочетания кнопок пока не назначены.

Меню SETTINGS содержит QNH, Average, Sound, Zero relative altitude и Back.
QNH редактируется с шагом 0,1 гПа, Average — с шагом 1 с. Удержание ускоряет
изменение повторением. Пока открыто редактирование, рабочие значения не меняются.
ОК применяет и сохраняет их, Назад отменяет. Сообщение RAM only означает, что
изменение применено, но запись во flash не удалась.

Для обнуления выбрать Zero relative altitude, затем коротким Вверх/Вниз переключить
NO на YES и нажать ОК. По умолчанию выбрано NO. Удержание Вверх/Вниз на этом экране
не меняет выбор. Без валидного давления ноль не изменяется и отображается сообщение.
Команда Serial `z` остаётся прямым обнулением для отладки.

Измерения и звуковая индикация продолжаются в меню. Меню возвращает на тот экран,
из которого было открыто. Подписи пока английские. Аппаратную проверку новых кнопок
выполнить после загрузки: короткие нажатия, удержания, отмена правки и подтверждение нуля.

## Дисплей ILI9341

Драйвер выбран по присланному описанию товара. Описание относится к 2,4-дюймовому
модулю, на фотографии указано 2,8 дюйма; фактическую совместимость проверяем по
изображению. По фото от 29 сентября выбран профиль с исходной областью
320 по ширине × 240 по высоте при rotation=0. Рабочая ориентация вертикальная:
rotation=1, ширина 240 и высота 320. Все страницы рассчитаны на эту область.
Стандартная библиотека предполагала при этом повороте 240×320: справа оставалась
полоса, а нижние строки появлялись сверху. Локальный адаптер ModuleDisplay меняет
границы отрисовки, сохраняя команду поворота. При нечётных поворотах область 240×320.
Это проверяемая по фото настройка геометрии, а не подтверждение модели контроллера.
Размер диагонали не меняет число пикселей. SPI настроен на 10 МГц.

| TFT | ESP32 |
|---|---|
| CS | GPIO27 |
| RESET | GPIO25 |
| DC | GPIO26 |
| SDI / MOSI | GPIO23 |
| SCK | GPIO18 |
| SDO / MISO | GPIO19 (для текущего вывода необязателен) |
| GND | GND |
| LED | 3V3 |
| VCC | 5V / VIN при питании ESP32 от USB, только при разомкнутой J1 |

Условия питания взяты из присланного описания: VCC=5 В с разомкнутой J1 либо
VCC=3,3 В с замкнутой J1. Перед подачей 5 В убедиться, что это соответствует
конкретной плате и J1 разомкнута. LED и сигнальные линии — только 3,3 В.
Подсветка питается от 3V3, не от GPIO. Проводку менять без USB-питания.

Контакты SD и T_* пока не подключать. На фото посадочное место U1 пустое:
заявление карточки товара о контроллере touch не подтверждено для этой платы.
Сенсорное управление не реализовано.

Команда `v` переключает страницы по кругу: вариометр → компас → диагностика.
Диагностический экран: чёрный фон, ДИАГНОСТИКА, индикатор батареи
и шесть строк: давление/температура, ускорение,
вращение, магнитное поле, RTC и состояние диагностики. Подписи пока английские,
показания IMU и магнитометра — сырые отсчёты. Следующее `v` возвращает основной
экран с крупной вертикальной скоростью, AVG, высотой QNH и относительной высотой.

Знак `!` рядом со временем означает OSF=1; время не устанавливается автоматически.
Команда `p` отключает Serial-телеметрию и опрос IMU/магнитометра на диагностическом
экране. Чтение давления, расчёт вариометра, звук и основной экран продолжают работать.
IMU/магнитометр опрашиваются раз в секунду только на странице диагностики с включённой
телеметрией. RTC читается раз в секунду, кроме времени теста баззера.
На странице компаса магнитометр опрашивается отдельно с частотой 10 Гц независимо
от Serial-телеметрии. Шкала обновляется до 5 раз/с, вращаясь под неподвижным
указателем. Под ней показаны угол 000–359 градусов и направление N/NE/E/SE/S/SW/W/NW.
Переход через север сглаживается по короткой дуге. При ошибке, переполнении или
отсутствии свежих данных более 0,5 с курс скрывается, появляется NO FRESH DATA.

Это предварительный магнитный угол `atan2(Y, X)` в системе осей датчика: держать
его плоскость XY горизонтально. Смещение нуля относительно корпуса, калибровка
магнитных искажений, магнитное склонение и компенсация наклона пока не заданы.
Поэтому экран помечен UNCALIBRATED; точность направления на север не подтверждена.
Перерисовываются только изменившиеся поля.
Если дисплей отключён, диагностика через Serial продолжает работать; успешная
сборка или отправка команд SPI не подтверждает наличие изображения.

Если видна только подсветка, проверить CS/DC/RESET/MOSI/SCK и питание по J1.
После проверки проводки отправить `t` для перерисовки или нажать EN для полного
повторного запуска дисплея. Пришлите фото результата для проверки цветов и ориентации.

## Сборка и запуск

В терминале PlatformIO:

```text
pio run
pio run --target upload
pio device monitor --baud 115200
```

После открытия монитора нажать EN на ESP32 для повторного стартового отчёта.
При нескольких последовательных портах указать нужный через `--upload-port COMx`
для загрузки и `--port COMx` для монитора. Скорость монитора уже задана в platformio.ini.

## Команды

В меню настроек добавлен `Buzzer test`: короткий импульс и тоны 700/1400/2100 Гц.
Тест завершается автоматически; ОК или Назад останавливает его и возвращает в меню.
Рабочий звук после теста остаётся выключенным; включить его можно пунктом `Sound`.

Для проверки лишней области экрана отправить `g`: рамка, четыре цветных угла и
сетка должны занимать всю матрицу. Каждое следующее `g` меняет поворот (1, 2, 3, 0).
Подпись показывает размеры, заданные драйвером, а не измеренное разрешение матрицы.
`t` или кнопка возвращает рабочий экран. Если за рамкой остаётся лишняя область,
нужно уточнить контроллер/разрешение дисплея по результатам этой проверки.
Частота SPI снижена с 20 до 10 МГц для проверки качества связи на проводах;
это не является подтверждённым исправлением геометрии дисплея.

| Команда | Действие |
|---|---|
| h | Справка |
| v | Вариометр → компас → диагностика |
| m | Включить/выключить рабочий звук |
| z | Обнулить относительную высоту |
| q1013.25 + Enter | Установить QNH, диапазон 800–1100 гПа, десятичная точка |
| a10 + Enter | Установить период AVG, диапазон 1–30 секунд |
| t | Полная перерисовка текущего экрана |
| g | Тест границ дисплея / следующий поворот; t — выход |
| s | Раздельное сканирование обеих шин I²C с указанием GPIO |
| d | Повторная проверка бародатчика, BMI160 и магнитометра QMC/HMC |
| r | Чтение времени и флага остановки генератора RTC |
| p | Включение/выключение Serial-телеметрии и диагностического опроса IMU/магнитометра |
| b | Короткий тест баззера: постоянный уровень, затем 700/1400/2100 Гц |
| x | Остановка теста и выключение рабочего звука |

Постоянный звук в первой фазе обычно указывает на активный баззер.
Разные высоты тона на трёх частотах — на пассивный. Отсутствие звука само по себе
не определяет тип: проверить питание и соединения. Включение предполагается высоким
уровнем S; если модуль звучит в покое, отключить его питание и уточнить схему.
Громкость 90 дБ и шесть уровней этим тестом не проверяются.

## Интерпретация

- 0x68: предполагаемый RTC; ACK не доказывает модель DS3231.
- 0x69: BMI160; CHIP_ID должен быть 0xD1. Неизвестные чипы не настраиваются.
- BMI160: ожидается PMU_STATUS=0x14 и ERR_REG=0x00 после включения акселерометра
  и гироскопа. Раз в секунду выводятся свежие сырые значения XYZ обоих датчиков.
  При наклоне меняются значения акселерометра; при вращении — гироскопа.
  У лежащего неподвижно датчика ускорение не равно нулю из-за силы тяжести.
  Это сырые отсчёты, не градусы наклона, не м/с² и не градусы/с.
- В BMI160 нет встроенного магнитометра; используется отдельный GY-273.
- На второй шине проверяются QMC5883L (0x0D) и HMC5883L (0x1E), с приоритетом QMC.
  В присланном отчёте обнаружен адрес 0x0D, что указывает на вероятный QMC5883L.
  Адрес сам по себе не подтверждает модель: сначала читается ID, затем проверяется
  запись и обратное чтение настроек. Неизвестный ID не настраивается.
- QMC5883L: ожидается CHIP_ID=0xFF. Режим 50 Гц, ±8 гаусс, OSR=512.
  Вывод `QMC5883L raw: magnetic XYZ=[...]` содержит сырые знаковые отсчёты XYZ.
  У QMC младший байт идёт первым, а порядок осей отличается от HMC.
  При переполнении измерения не выводятся. Пометка `older samples skipped` ожидаема:
  датчик измеряет 50 раз/с, а диагностика читает последнее измерение раз/с.
  Ответ FF и успешная настройка означают совместимость с протоколом, не проверку подлинности.
- 0x1E на второй шине (SDA=16, SCL=17): HMC5883L; ожидается ID `48 34 33` (`H43`). Драйвер проверяет ID перед
  записью настроек и считывает настройки обратно для проверки. Режим: 15 Гц,
  усреднение 8 измерений, диапазон ±1,3 гаусс, непрерывное измерение.
  Строки `HMC5883L raw: magnetic XYZ=[...]` содержат знаковые сырые отсчёты
  в системе координат магнитометра. Порядок регистров X/Z/Y преобразован в X/Y/Z.
  Переполнение выдаёт отдельное сообщение вместо некорректных измерений.
  Если модуль не найден или ID другой, прошивка продолжает проверку остальных датчиков.
  Сам по себе адрес другого устройства не подтверждает его модель.
- Магнитометр пока не откалиброван; на странице компаса показывается предварительный
  угол по XY. Для точного курса потребуются калибровка и согласование его осей
  с BMI160 после фиксации модулей в корпусе.
- 0x76/0x77, ID=0x58: BMP280; ID=0x60: BME280.
- 0x50–0x57: возможная EEPROM RTC; диагностика её не изменяет.
- OSF=1: время RTC недостоверно после остановки генератора; автоматической установки нет.

Для проверки рабочего режима сохранить строки VARIO в покое, при подъёме и опускании,
а также фото основного экрана. Для диагностики датчиков переключиться командой `v`.

## Проверки расчётов на компьютере

Тесты не требуют платы: покой, шум давления, постоянный подъём/снижение, изменение
QNH, недопустимые данные, перерывы измерений, переполнение millis и пороги звука.

```text
g++ -std=c++11 -Wall -Wextra -pedantic -I include test/vario_host.cpp -o .pio/vario_host.exe
.pio/vario_host.exe
g++ -std=c++11 -Wall -Wextra -pedantic -I include test/compass_host.cpp -o .pio/compass_host.exe
.pio/compass_host.exe
pio run
g++ -std=c++14 -Wall -Wextra -DARDUINO=10800 -I include -I test/arduino_stub -I .pio/libdeps/esp32doit-devkit-v1/Bounce2/src test/buttons_host.cpp .pio/libdeps/esp32doit-devkit-v1/Bounce2/src/Bounce2.cpp -o .pio/buttons_host.exe
.pio/buttons_host.exe
```

Дребезг всех четырёх кнопок подавляет [Bounce2 2.72](https://github.com/thomasfredericks/Bounce2)
с интервалом стабильности 30 мс. Короткие/долгие нажатия и автоповтор
обрабатываются после фильтрации библиотекой, без задержек `delay()`.
Подтяжки GPIO34/35 резисторами 10 кОм к 3,3 В остаются обязательными.

Тесты кнопок используют исходный код Bounce2 и имитацию GPIO/времени на компьютере.
Проверяются дребезг, разделение короткого и долгого нажатия, повторы,
зажатую при запуске кнопку, переполнение таймера, отмену/сохранение правок,
ограничения значений и подтверждение обнуления.
