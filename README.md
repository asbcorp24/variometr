# Вариометр на ESP32

Прошивка прототипа вариометра для **ESP32 DevKit V1, 30 выводов**. Выводит вертикальную скорость, высоту, компас и заряд аккумулятора на SPI TFT. Управление — четырьмя кнопками, интерфейс дисплея на русском.

Проект: [asbcorp24/variometr](https://github.com/asbcorp24/variometr).

## Что реализовано

| Функция | Текущее состояние |
|---|---|
| Вертикальная скорость | По BMP280/BME280, с фильтрацией |
| Высота | По QNH и относительно выбранного нуля |
| Средняя скорость | Период 1–30 с, по умолчанию 10 с |
| Звук | Подъём, снижение, сигнал сильного снижения; отдельный тест |
| Компас | Вращающаяся шкала и угол 0–359°, предварительный расчёт по XY |
| BMI160 | Диагностика ускорения и вращения; в расчёте вариометра пока не участвует |
| RTC | Чтение времени и признака его достоверности |
| MAX17048 | Поддержка чтения заряда/напряжения; пока без модуля — 100% / ДЕМО |
| Настройки | QNH и период усреднения сохраняются во flash |
| Интерфейс | Русский растровый шрифт, включая Ё, надписи прописными буквами |
| Кнопки | Bounce2: дребезг 30 мс, короткие/долгие нажатия, автоповтор |

Это прототип: аппаратная работа новой функции подтверждается проверкой на собранном приборе. Сборка и программные тесты не подтверждают точность полётных показаний.

<a id="pinout"></a>
## Общая распиновка ESP32

Номера ниже — **GPIO на маркировке платы**, а не порядковые номера контактов разъёма. Расположение контактов у разных 30-пиновых плат отличается: ориентироваться по надписям своей ESP32.

| ESP32 | Назначение | Подключение |
|---|---|---|
| GPIO21 | SDA основной I²C | SDA RTC, BMI160, BMP/BME280 и MAX17048 |
| GPIO22 | SCL основной I²C | SCL тех же модулей |
| GPIO16 | SDA второй I²C | SDA/SDI магнитометра GY-273 |
| GPIO17 | SCL второй I²C | SCL магнитометра GY-273 |
| GPIO18 | SPI SCK | SCK TFT |
| GPIO23 | SPI MOSI | SDI/MOSI TFT |
| GPIO19 | SPI MISO | SDO/MISO TFT; для вывода изображения необязателен |
| GPIO27 | TFT CS | CS TFT |
| GPIO26 | TFT DC | DC / D-C / RS TFT |
| GPIO25 | TFT RESET | RESET / RST TFT |
| GPIO14 | Баззер | Сигнал S модуля баззера |
| GPIO32 | Назад / экран | Кнопка на GND; внутренняя подтяжка |
| GPIO33 | Вверх / плюс | Кнопка на GND; внутренняя подтяжка |
| GPIO34 | Вниз / минус | Кнопка на GND + внешний резистор 10 кОм к 3V3 |
| GPIO35 | ОК | Кнопка на GND + внешний резистор 10 кОм к 3V3 |
| 3V3 | Питание модулей | RTC, BMI160, барометр, магнитометр, баззер; LED TFT |
| 5V / VIN | Питание VCC TFT от USB | Только для TFT с поддержкой 5 В и разомкнутой J1 |
| GND | Общая земля | Все модули, кнопки и аккумуляторная часть согласно её схеме |

GPIO16/17 уже заняты магнитометром. GPIO34/35 — только входы, у них нет внутренних подтяжек.

### Распределение I²C

```text
ESP32 GPIO21 (SDA) ──┬── RTC SDA
                    ├── BMI160 SDA
                    ├── BMP280/BME280 SDA
                    └── MAX17048 SDA/SDI (после установки)

ESP32 GPIO22 (SCL) ──┬── RTC SCL
                    ├── BMI160 SCL
                    ├── BMP280/BME280 SCL
                    └── MAX17048 SCL (после установки)

ESP32 GPIO16 (SDA) ───── GY-273 SDA/SDI
ESP32 GPIO17 (SCL) ───── GY-273 SCL
```

Первая и вторая шины не соединяются между собой. Несколько устройств на одной шине подключаются параллельно: отдельных GPIO для каждого датчика не требуется. При нехватке разъёмов использовать разветвитель или общие контактные ряды.

Обе шины работают на 100 кГц. Подтяжки SDA/SCL должны идти к 3,3 В. Если на модулях второй шины нет подтяжек, добавить по 4,7 кОм от SDA и SCL к 3V3. Подтяжки первой шины вторую не обслуживают.

<a id="modules"></a>
## Подключение модулей

Проводку менять при отключённом питании. Для первого запуска ESP32 питается от USB, земли всех модулей объединены. На сигнальные GPIO ESP32 подавать уровни 3,3 В.

### BMP280 / BME280

| Вывод модуля | Подключить |
|---|---|
| VCC | 3V3, если модуль поддерживает питание 3,3 В |
| GND | GND |
| SDA / SDI | GPIO21 |
| SCL / SCK | GPIO22 |
| CS / CSB, если выведен | 3V3 для I²C |
| SDO, если выведен | GND для 0x76; 3V3 для 0x77 |

Код проверяет оба адреса. В имеющейся сборке найден **BMP280: 0x76, CHIP_ID=0x58**. Для BME280 ожидается ID=0x60. Ориентироваться по маркировке конкретного модуля; готовые перемычки могут уже задавать режим и адрес.

### GY-BMI160

| Вывод модуля | Подключить |
|---|---|
| VCC | 3V3 |
| GND | GND |
| SDA | GPIO21 |
| SCL | GPIO22 |
| SDO / SA0 | 3V3 — адрес 0x69 |
| CS / CSB | 3V3 — режим I²C |
| INT1 / INT2 и вспомогательные выводы | Оставить неподключёнными |

**Адрес 0x68 занят RTC**, поэтому BMI160 должен быть на 0x69. Код не настраивает BMI160 по адресу 0x68. Если SDO на плате уже жёстко соединён с GND, сначала изменить штатную перемычку по схеме модуля, затем подключать к 3V3.

Ожидаемые данные диагностики: CHIP_ID=0xD1, PMU_STATUS=0x14, ERR_REG=0x00. MPU9250/другой MPU в текущей сборке не используется.

### RTC HW-084

| Вывод модуля | Подключить |
|---|---|
| VCC | 3V3 |
| GND | GND |
| SDA | GPIO21 |
| SCL | GPIO22 |
| SQW / 32K | Оставить неподключёнными |

RTC читается как DS3231 по адресу 0x68; адрес сам по себе модель не доказывает. На модуле также обнаружен 0x57 — предполагаемая EEPROM, прошивка её не изменяет.

Если OSF=1, время недостоверно после остановки генератора: на дисплее появляется `!`. Прошивка читает часы, но не устанавливает время и не сбрасывает OSF.

У некоторых RTC-модулей есть цепь подзарядки батареи. Для обычной CR2032 её нужно проверить и при необходимости отключить. Первую проверку можно провести без резервной батарейки.

### Магнитометр GY-273

| Вывод модуля | Подключить |
|---|---|
| VCC | 3V3 |
| GND | GND |
| SDA / SDI | GPIO16 |
| SCL | GPIO17 |
| DRDY, если имеется | Оставить неподключённым |

Несмотря на название HMC5883L в описании модуля, в имеющейся сборке обнаружен **QMC5883L-совместимый датчик: 0x0D, CHIP_ID=0xFF**. Код поддерживает QMC5883L и HMC5883L, приоритет — QMC.

| Датчик | Адрес | Проверка | Режим |
|---|---|---|---|
| QMC5883L | 0x0D | CHIP_ID=0xFF и чтение настроек обратно | 50 Гц, ±8 Гс, OSR=512 |
| HMC5883L | 0x1E | ID `48 34 33` / `H43` и чтение настроек обратно | 15 Гц, 8 усреднений, ±1,3 Гс |

Успешная проверка означает совместимость с протоколом, но не подтверждает подлинность чипа. Держать магнитометр вдали от магнитов, стали, баззера и силовых проводов.

### TFT по SPI

| Вывод TFT | Подключить |
|---|---|
| CS | GPIO27 |
| RESET / RST | GPIO25 |
| DC / RS | GPIO26 |
| SDI / MOSI | GPIO23 |
| SCK | GPIO18 |
| SDO / MISO | GPIO19, необязателен для текущего вывода |
| GND | GND |
| LED | 3V3, напрямую от питания, не от GPIO |
| VCC | 5V от USB при поддержке 5 В и разомкнутой J1 |
| SD_* и T_* | Пока не подключать |

Для описанного пользователем TFT: **VCC=5 В при разомкнутой J1** либо **VCC=3,3 В при замкнутой J1**. Перед подключением проверить, что это соответствует конкретной плате. Подсветка LED и сигналы — 3,3 В.

Используется Adafruit ILI9341, SPI 10 МГц. Рабочий экран **вертикальный: ширина 240, высота 320**. Для имеющегося модуля установлен профиль `ModuleDisplay`: исходная область 320×240, рабочий `DEFAULT_ROTATION=1` даёт 240×320. Профиль выбран по фотографиям, где стандартные границы драйвера оставляли полосу и переносили нижние строки наверх; модель контроллера отдельно не подтверждена.

Для обычного модуля с иной геометрией этот профиль может не подойти. Проверка `g` показывает рамку и четыре угла; `t` возвращает рабочий экран. Параметры и распиновка TFT находятся в [src/diagnostic_display.cpp](src/diagnostic_display.cpp).

TouchScreen и SD не реализованы. На присланном фото место U1 пустое, поэтому наличие установленного контроллера touch для этой платы не подтверждено.

### Баззер

| Keyestudio / совместимый модуль | Подключить |
|---|---|
| G / GND | GND |
| V / VCC | 3V3 для используемого модуля |
| S / Signal | GPIO14 |

Код управляет сигнальным входом модуля. Для отдельного динамика или другого баззера схема драйвера может отличаться.

Тест: импульс постоянного уровня 400 мс, затем 700, 1400 и 2100 Гц с паузами. Разные высоты тона обычно указывают на пассивный баззер; постоянный звук от первого импульса — на активный. Отсутствие звука само по себе тип не определяет.

### Четыре кнопки

Кнопки нормально разомкнутые, без фиксации: каждая замыкает свой GPIO на GND. GPIO32/33 используют внутренние подтяжки. Для GPIO34/35 нужны **два отдельных резистора по 10 кОм к 3V3**:

```text
3V3 ──[10 кОм]──┬── GPIO34 / GPIO35
                │
              кнопка
                │
               GND
```

Подтяжки GPIO34/35 нужны и до установки кнопок, иначе свободные входы могут создавать ложные нажатия. У четырёхконтактной тактовой кнопки выбрать пару, соединяющуюся при нажатии: часть её выводов уже соединена постоянно.

### MAX17048 — подключение предусмотрено

| Adafruit MAX17048 | Подключить |
|---|---|
| SDA / SDI | GPIO21, параллельно остальным устройствам первой шины |
| SCL | GPIO22 |
| GND | Общая земля |
| VIN | 3V3 — питание логической части платы Adafruit |
| BAT / JST аккумулятора | Одна Li-ion/LiPo ячейка: 3,7 В номинально, до 4,2 В |
| INT / QStart | Оставить неподключёнными |

Сам MAX17048 на плате Adafruit питается от аккумулятора: без подключённой батареи может не отвечать на I²C. BAT не соединять с 3V3 ESP32. Проверить полярность JST. Для платы другого производителя свериться с её схемой: обозначения VIN/VCC/BAT могут отличаться.

MAX17048 измеряет батарею; для зарядки и питания ESP32 требуется соответствующая зарядная и преобразующая схема. [Выводы модуля Adafruit](https://learn.adafruit.com/adafruit-max17048-lipoly-liion-fuel-gauge-and-battery-monitor/pinouts).

<a id="build"></a>
## Сборка и загрузка

Нужны Git и PlatformIO Core либо расширение PlatformIO для VS Code. Зависимости устанавливаются по [platformio.ini](platformio.ini).

```powershell
git clone https://github.com/asbcorp24/variometr.git
cd variometr
pio run
pio run --target upload
pio device monitor --baud 115200
```

Параметры проекта: `esp32doit-devkit-v1`, Arduino, платформа `espressif32@6.10.0`, Serial 115200. Используются Adafruit BMP280, Adafruit BME280, Adafruit ILI9341 и Bounce2; драйверы BMI160, магнитометра и MAX17048 находятся в проекте.

При нескольких портах:

```powershell
pio device list
pio run --target upload --upload-port COM5
pio device monitor --port COM5 --baud 115200
```

Заменить COM5 своим портом. Перед загрузкой закрыть монитор порта. Если плата не входит в загрузчик автоматически, использовать BOOT/EN согласно работе своей ESP32. После открытия монитора нажать EN для повторного стартового отчёта.

<a id="start"></a>
## Первый запуск

1. Проверить питание, общую землю, адрес BMI160 и подтяжки кнопок.
2. Собрать и загрузить прошивку. Открыть Serial на 115200, нажать EN.
3. Проверить обе шины I²C: первая — 0x57, 0x68, 0x69, 0x76 в текущей сборке; вторая — 0x0D. MAX17048 позже добавит 0x36 на первой.
4. Дождаться валидного давления и заполнения окна скорости — примерно 1,5 с. На экране «ПРОГРЕВ» сменится на «ГОТОВ».
5. Оставить прибор в покое на 10–15 с: скорость должна быть около нуля.
6. Выполнить «ОБНУЛИТЬ ВЫСОТУ» или отправить `z`.
7. Проверить «ТЕСТ ПИЩАЛКИ», затем включить рабочий звук через «ЗВУК», удержание «Назад» или `m`.
8. Плавно поднять прибор на 1–2 м и остановить: скорость сначала положительная, затем возвращается к нулю. При опускании — отрицательная. Реакция фильтра задерживается примерно на 1–2 с.

При запуске рабочий звук разрешён настройкой SOUND_ENABLED_ON_BOOT=true; до готовности фильтра и в зоне тишины баззер молчит. MAX17048 пока отсутствует: **100% / ДЕМО** — условный индикатор, а не измеренный заряд.

<a id="controls"></a>
## Экраны и кнопки

Короткое нажатие «Назад» переключает страницы по кругу: **вариометр → компас → диагностика**. «ОК» открывает настройки. После выхода из меню возвращается та же страница.

- **Вариометр:** вертикальная скорость, средняя скорость, высота QNH, относительная высота, QNH, период среднего, время и состояние звука.
- **Компас:** шкала вращается под неподвижным указателем; показаны градусы и С/СВ/В/ЮВ/Ю/ЮЗ/З/СЗ.
- **Диагностика:** давление/температура, сырые XYZ ускорения, вращения и магнитного поля, RTC, состояние диагностики.
- **Батарея:** в правом верхнем углу всех трёх страниц и меню — значок, процент и «ДЕМО», напряжение либо ошибка.

| Кнопка | Короткое нажатие | Удержание от 0,8 с |
|---|---|---|
| Назад, GPIO32 | Следующий экран; в меню отменить/выйти | Переключить рабочий звук |
| Вверх, GPIO33 | Предыдущий пункт / увеличить значение | Автоповтор каждые 120 мс |
| Вниз, GPIO34 | Следующий пункт / уменьшить значение | Автоповтор каждые 120 мс |
| ОК, GPIO35 | Открыть меню, выбрать или подтвердить | Открыть меню с рабочей страницы |

В тесте пищалки короткое или долгое нажатие ОК/Назад останавливает тест и возвращает в список. В подтверждении нуля Вверх/Вниз переключают выбор только короткими нажатиями.

Короткое действие выполняется при отпускании. После долгого нажатия короткое не повторяется. Зажатая при запуске кнопка игнорируется до отпускания. Фильтрация дребезга — Bounce2, 30 мс. Сочетания кнопок не назначены.

<a id="settings"></a>
## Настройки

| Пункт | Действие |
|---|---|
| QNH | 800–1100 гПа, шаг 0,1; стандартное начальное значение 1013,25 |
| СРЕДНЕЕ | Период 1–30 с, шаг 1; начальное значение 10 с |
| ЗВУК | Включить/выключить рабочую звуковую индикацию |
| ОБНУЛИТЬ ВЫСОТУ | Подтверждение НЕТ/ДА; начальный выбор НЕТ |
| ТЕСТ ПИЩАЛКИ | Импульс и три тона; рабочий звук после теста выключен |
| НАЗАД | Закрыть меню |

Вверх/Вниз меняют черновое значение; ОК применяет и сохраняет, Назад отменяет. QNH и период среднего хранятся во flash через Preferences и восстанавливаются после перезапуска. При ошибке сохранения настройка действует только до перезапуска. Относительный ноль и разрешение звука не сохраняются.

QNH — опорное давление на уровне моря, а не показание самого бародатчика. 1013,25 гПа — стандартная исходная опора. Для корректной абсолютной высоты нужно задать актуальное местное QNH. Изменение QNH перезапускает фильтр; относительный ноль автоматически задаётся первым валидным измерением после включения и меняется обнулением.

<a id="sound"></a>
## Как включается звук

В [src/main.cpp](src/main.cpp):

```cpp
constexpr bool SOUND_ENABLED_ON_BOOT = true;
bool settingsReady = false;
bool audioEnabled = SOUND_ENABLED_ON_BOOT;
```

`audioEnabled` разрешает рабочий звук. При старте берётся значение `SOUND_ENABLED_ON_BOOT`, сейчас `true`. Команда `m`, меню «ЗВУК» и удержание «Назад» переключают этот флаг. Команда `x` выключает звук. Для отключения при старте установить `SOUND_ENABLED_ON_BOOT = false` и пересобрать прошивку. В Serial выводятся дата сборки, `Boot sound setting` и фактическое состояние звука. Если после изменения на экране всё ещё «БЕЗ ЗВУКА», проверить загрузку новой сборки, команды `x`/`b`, сообщения `Audio initialization failed` и `Button: muted`; последнее может появиться из-за замыкания GPIO32 на GND или плохой проводки.

`varioSoundTick()` вызывается из `loop()`: проверяет разрешение и готовность барометрических данных, выбирает частоту, затем `ledcWriteTone(0, frequency)` выводит сигнал на **GPIO14**, LEDC-канал 0. Кривые звука находятся в [include/vario.h](include/vario.h), функции `soundMode()` и `tone()`.

| Движение | Порог включения | Порог возврата | Звук |
|---|---|---|---|
| Подъём | От +0,2 м/с | +0,1 м/с и ниже | Прерывистый, 800–1800 Гц; писк учащается |
| Снижение | −2 м/с и ниже | −1,8 м/с и выше | Постоянный 350 Гц |
| Сильное снижение | −10 м/с и ниже | −9,5 м/с и выше | Чередование 700/1800 Гц |

В покое включённый вариометр обычно молчит. Для проверки проводки использовать `b` или «ТЕСТ ПИЩАЛКИ». Тест занимает около 2,8 с; его можно прервать. Громкость фиксирована, регулировка уровней пока отсутствует.

### Расчёт скорости

Целевой опрос барометра — 10 Гц, обновление экрана — до 5 Гц. Высота вычисляется по барометрической формуле; сглаживание высоты — 0,35 с. Скорость — наклон прямой по 16 последним измерениям с учётом времени, затем сглаживание 0,3 с. Среднее — среднее доступных скоростей за выбранный период.

Ошибка давления или перерыв более 0,5 с сбрасывают скорость и блокируют звук до заполнения нового окна. QNH, сканирование `s`, повторная инициализация барометра `d` и тест `b` также вызывают прогрев фильтра. Бародатчик настроен на температуру ×2, давление ×16, аппаратный фильтр выключен. BMI160 в расчёте скорости не используется.

<a id="serial"></a>
## Команды Serial

Скорость — **115200 бод**. Одиночные команды не требуют Enter. Для `q` и `a` после числа нужен Enter; десятичный разделитель — точка.

| Команда | Действие |
|---|---|
| `h` | Справка |
| `v` | Вариометр → компас → диагностика |
| `m` | Переключить рабочий звук |
| `x` | Остановить тест и выключить рабочий звук |
| `b` | Тест пищалки; выключает рабочий звук и сбрасывает фильтр |
| `z` | Сразу обнулить относительную высоту при валидном давлении |
| `q1013.25` + Enter | Установить и сохранить QNH, 800–1100 гПа |
| `a10` + Enter | Установить и сохранить период среднего, 1–30 с |
| `s` | Просканировать обе I²C-шины; сбросить фильтр |
| `d` | Повторно определить/настроить барометр, BMI160 и магнитометр |
| `r` | Показать RTC и OSF |
| `p` | Переключить Serial-телеметрию и диагностический опрос IMU/магнитометра |
| `t` | Перерисовать текущий экран; выйти из теста геометрии |
| `g` | Тест рамки/углов дисплея, следующее нажатие меняет поворот |

Выключение телеметрии `p` сохраняет расчёт вариометра, звук, чтение RTC, монитор батареи и опрос компаса. В диагностике IMU/магнитометр читаются раз в секунду при включённой телеметрии. Компас читает магнитометр отдельно до 10 раз/с, независимо от `p`.

MAX17048 проверяется автоматически, `d` для него не требуется. RTC и EEPROM командами не перезаписываются. В тесте геометрии `t` или кнопка возвращают вертикальный рабочий экран.

<a id="compass"></a>
## Компас

Используется предварительный угол `atan2(Y, X)` магнитометра, нормализованный в 0–359°. Сглаживание проходит по короткой дуге, включая переход 359° → 0°. При ошибке чтения, переполнении или отсутствии свежих данных 0,5 с курс скрывается и появляется «НЕТ ДАННЫХ».

Держать плоскость XY датчика горизонтально. Калибровка магнитных искажений, согласование осей с корпусом, магнитное склонение и компенсация наклона пока не заданы. Поэтому на экране есть надпись «БЕЗ КАЛИБРОВКИ»: точное направление на север ещё не подтверждено.

<a id="battery"></a>
## Батарея MAX17048

Адрес — **0x36 на основной I²C-шине**. Поддержка подготовлена, физического модуля в текущей сборке ещё нет.

| Состояние | Экран |
|---|---|
| Модуль ещё не обнаружен | **100% / ДЕМО**, условный полный значок |
| Получены корректные данные | Измеренный заряд и напряжение |
| Ошибка чтения/версии либо потеря уже обнаруженного датчика | **--% / ОШИБКА** |

Поиск отсутствующего датчика — раз в 5 с, опрос найденного — раз в 1 с. Подключение поддерживается без изменения прошивки; проводку менять при выключенном питании. После потери уже обнаруженного датчика демонстрационные 100% не возвращаются до перезапуска. Данные старше 3 с считаются недостоверными.

Драйвер проверяет версию и читает VCELL/SOC, не выполняет сброс или quick-start. Процент ограничен диапазоном 0–100. Цвет значка измеренного заряда: зелёный выше 20%, оранжевый при 20% и ниже; демонстрация — жёлтая, ошибка — красная. Это индикация, без автоматического отключения или звукового предупреждения разряда.

<a id="troubleshooting"></a>
## Диагностика неисправностей

| Симптом | Проверка |
|---|---|
| Белый/тёмный экран | Питание VCC и LED, положение J1, общая земля, CS/DC/RST/MOSI/SCK; затем EN или `t` |
| Полоса мусора, строки переносятся наверх | `g`: вся рамка и четыре угла должны быть видны; проверить профиль ModuleDisplay и контроллер TFT |
| Экран перевёрнут | Проверить DEFAULT_ROTATION; повороты 1 и 3 в этом профиле вертикальные, отличаются на 180° |
| Русские символы неверны | Загрузить актуальную прошивку; исходники UTF-8, используется russian_gfx.h |
| Нет BMP/BME280 | Питание, режим I²C, адрес 0x76/0x77; `s`, затем `d` |
| Нет BMI160 | SDO/SA0=3V3, CS/CSB=3V3, адрес 0x69, CHIP_ID=0xD1 |
| Магнитометр не найден | SDA16/SCL17, питание, общая земля, подтяжки; проверить обе модели, не только HMC |
| Ложные нажатия | Подтяжки 10 кОм на GPIO34/35, контакты тактовой кнопки, проводка |
| Баззер молчит | Проверить `b`, GPIO14, G/V/S; в покое рабочий звук может быть включён, но частота нулевая |
| RTC показывает 2000 год и `!` | OSF=1, часы не установлены; автоматической установки нет |
| Батарея 100% / ДЕМО | Пока условное значение; проверить появление 0x36 и подключение аккумулятора к MAX17048 |
| Батарея --% / ОШИБКА | Проверить питание аккумулятором, I²C, регистр версии и сообщения Serial |
| Serial нечитаем | Установить 115200, проверить порт и соединение USB |

ACK при сканировании показывает только присутствие адреса. Модель подтверждается дополнительными регистрами; для RTC это остаётся предположением.

### Проверки на компьютере

Нужен `g++` в PATH. Сначала `pio run` установит Bounce2 и создаст `.pio`. Команды ниже — для PowerShell на Windows:

```powershell
pio run

g++ -std=c++11 -Wall -Wextra -I include test/vario_host.cpp -o .pio/vario_host.exe
& ./.pio/vario_host.exe

g++ -std=c++11 -Wall -Wextra -I include test/compass_host.cpp -o .pio/compass_host.exe
& ./.pio/compass_host.exe

g++ -std=c++11 -Wall -Wextra -I include test/battery_host.cpp -o .pio/battery_host.exe
& ./.pio/battery_host.exe

g++ -std=c++11 -Wall -Wextra -I include test/russian_host.cpp -o .pio/russian_host.exe
& ./.pio/russian_host.exe

g++ -std=c++14 -Wall -Wextra -DARDUINO=10800 -I include -I test/arduino_stub -I .pio/libdeps/esp32doit-devkit-v1/Bounce2/src test/buttons_host.cpp .pio/libdeps/esp32doit-devkit-v1/Bounce2/src/Bounce2.cpp -o .pio/buttons_host.exe
& ./.pio/buttons_host.exe
```

Проверяются шум/подъём/снижение, QNH, разрывы данных, звуковые пороги, переход компаса через север, ошибки батареи, кириллица, реальный код Bounce2, жесты и меню. Физические показания датчиков, изображение и звук проверяются отдельно на приборе.

<a id="limitations"></a>
## Ограничения и документация
