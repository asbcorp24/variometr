# Обновление для новой платы: памятка для Анатолия

## Что изменено

- Отдельные профили SPI TFT ILI9488 / ILI9486 3.5, 480×320; рабочая ориентация
  вертикальная, ширина 320 и высота 480. Интерфейс использует новые размеры.
- Журнал полётов во внутренней flash, просмотр статистики и незавершённых записей.
- Дата/время и часовой пояс на самом устройстве, UTC в RTC после явной настройки.
- INA228: фактическое напряжение и приблизительный процент по напряжению после
  подтверждения числа ячеек; без демонстрационных 100%.
- Прежние вариометр, компас, русский язык, кнопки Bounce2 и тест звука сохранены.

## Перед выбором прошивки

Надпись `3.5 SPI 480*320 V1.0` сама по себе не устанавливает контроллер. Нужно
подтвердить ILI9488 / ILI9486 по маркировке или документации конкретного модуля.
Выбор драйвера по одной диагонали может дать белый экран или неверные цвета.

| Контроллер | Окружение PlatformIO |
|---|---|
| Подтверждённый ILI9488, SPI | `esp32_ili9488` |
| Подтверждённый ILI9486, SPI | `esp32_ili9486` |
| Прежний небольшой дисплей | `esp32doit-devkit-v1` |

До подтверждения контроллера выбранный по умолчанию профиль оставлен прежним.
Новый экран прошивать только с явным `-e` нужного окружения.
ILI9488 использует 18-битные SPI-передачи; их обеспечивает TFT_eSPI.

## Подключение

Сигналы TFT: MOSI=23, MISO=19 (если нужен), SCK=18, CS=27, DC=26, RESET=25.
Питание VCC/подсветки нового модуля сверять с его собственной схемой: указания
про J1 старого TFT не переносятся автоматически на новую плату.
Touch и SD пока не включены. Если ILI9488 не освобождает MISO, не подключать его
к общей линии других SPI-устройств без проверки; сейчас SD в проекте не используется.

INA228 по умолчанию на основной шине: SDA=GPIO21, SCL=GPIO22, адрес 0x40.
Логические VIN=3V3 и GND=общая земля. Измеряемое напряжение подать на VBUS
согласно схеме конкретного монтажа; наличие связи по I²C ещё не означает,
что аккумулятор подключён к измерительному входу.

Для платы Adafruit по умолчанию перемычка VBUS разомкнута (low-side).
High-side/low-side включение и положение перемычки сверять по
[схеме производителя](https://learn.adafruit.com/adafruit-ina228-i2c-power-monitor/pinouts).
Силовой VIN+/VIN− не путать с логическим VIN.

В меню «АККУМУЛЯТОР» подтвердить число последовательных Li-ion ячеек 1…6.
Пока число не задано — фактическое напряжение и --%, после — оценка с `~`.
На присланном изображении шунт R015: в `include/hardware_config.h` уже установлено
0,015 Ом. Это включает расчёт тока; при замене платы сверить маркировку её шунта.
Ноль в этой настройке отключает показания тока. Ёмкость/учёт мА·ч пока не используются.

## Загрузка и проверка

Пример только для подтверждённого ILI9488:

```powershell
pio device list
pio run -e esp32_ili9488
pio run -e esp32_ili9488 --target upload --upload-port COM5
pio device monitor --port COM5 --baud 115200
```

COM5 заменить фактическим USB-портом ESP32. Системный COM1 сам по себе не является
подключённой ESP32. Для ILI9486 заменить имя окружения.

Не выполнять `erase`, `uploadfs` и смену разделов поверх журнала. Обычная загрузка
приложения с прежней таблицей разделов сохраняет NVS и LittleFS.

После загрузки:

1. Проверить рамку `g` и вернуть экран `t`; должны быть видны все четыре угла.
2. Проверить I²C: BMP280 0x76, RTC 0x68, BMI160 0x69, INA228 0x40 на первой шине;
   магнитометр 0x0D на второй.
3. Выбрать «ЧАСОВОЙ ПОЯС», затем «ДАТА И ВРЕМЯ», сохранить последним ОК.
4. Подтвердить число ячеек, сравнить показанное напряжение с мультиметром.
5. Проверить «ТЕСТ ПИЩАЛКИ», затем включить рабочий звук.
6. «НАЧАТЬ ПОЛЁТ» → ДА, плавно поднять/опустить прибор, затем «ЗАВЕРШИТЬ ПОЛЁТ» → ДА.
7. Открыть «ЖУРНАЛ ПОЛЁТОВ», проверить длительность и максимумы, перезапустить и проверить сохранение.
8. Отдельно испытать отключение питания во время тестовой записи и отметку незавершённого полёта.

Запись сейчас ручная: автоматическое определение взлёта/посадки не включено.
Максимальная скорость — вертикальная, GPS/горизонтальной скорости нет.
В будущем приложение сможет читать отдельные файлы формата, описанного в
[FLIGHT_LOG_FORMAT.md](FLIGHT_LOG_FORMAT.md).

На этапе подготовки компьютер видел только системный COM1, поэтому физическая
прошивка и проверка нового дисплея/INA228 ещё не подтверждены.
