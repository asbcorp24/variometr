# Магнитометр I2C 0x2C — изменения для QMC5883P

## Зачем нужен этот файл

На плате вариометра магнитометр подключён к отдельной I2C-шине ESP32:

- SDA: GPIO16
- SCL: GPIO17
- объект шины в прошивке: `magnetWire(1)`

Текущая версия `src/main.cpp` поддерживает:

- QMC5883L: адрес `0x0D`
- HMC5883L: адрес `0x1E`

Если I2C-сканер на GPIO16/GPIO17 обнаруживает устройство по адресу `0x2C`, его нельзя просто объявить QMC5883L с новым адресом. Для варианта QMC5883P/совместимого устройства требуется отдельная ветка драйвера, потому что карта регистров отличается.

## Где менять код

Основные изменения выполняются в:

`src/main.cpp`

Текущий блок адресов находится рядом с:

```cpp
bool hmcReady = false;
constexpr uint8_t HMC_ADDRESS = 0x1E;
bool qmcReady = false;
constexpr uint8_t QMC_ADDRESS = 0x0D;
```

Для нового устройства следует добавить отдельный флаг и адрес, например:

```cpp
bool qmcPReady = false;
constexpr uint8_t QMCP_ADDRESS = 0x2C;
```

Не заменять `QMC_ADDRESS = 0x0D` на `0x2C`: это сломает поддержку существующего QMC5883L.

## Регистры устройства 0x2C

Для отдельного драйвера QMC5883P используются свои регистры. Базовые определения:

```cpp
constexpr uint8_t QMCP_REG_ID     = 0x00;
constexpr uint8_t QMCP_REG_DATA_X = 0x01;
constexpr uint8_t QMCP_REG_STATUS = 0x09;
constexpr uint8_t QMCP_REG_CTRL1  = 0x0A;
constexpr uint8_t QMCP_REG_CTRL2  = 0x0B;
```

Перед окончательной настройкой конфигурационных битов желательно проверить маркировку фактически установленной микросхемы/даташит конкретного варианта модуля.

## Что нужно добавить

В `src/main.cpp` нужна отдельная функция:

```cpp
bool detectQmcP();
```

Она должна:

1. Проверить ACK на `0x2C`.
2. Прочитать идентификационный/контрольный регистр, если он доступен для установленного варианта.
3. Выполнить инициализацию именно QMC5883P.
4. Проверить записанные настройки.
5. Только после успешной проверки установить `qmcPReady = true`.

Также нужна отдельная функция чтения, например:

```cpp
void printQmcP();
```

Чтение XYZ для варианта с данными от `0x01`:

```cpp
uint8_t data[6];

if (readBytes(QMCP_ADDRESS, QMCP_REG_DATA_X, data, sizeof(data), magnetWire)) {
    int16_t x = int16_t(uint16_t(data[0]) | (uint16_t(data[1]) << 8));
    int16_t y = int16_t(uint16_t(data[2]) | (uint16_t(data[3]) << 8));
    int16_t z = int16_t(uint16_t(data[4]) | (uint16_t(data[5]) << 8));
}
```

## detectMagnetometer()

Сейчас прошивка сначала вызывает `detectQmc()`, затем проверяет HMC5883L.

После добавления драйвера порядок можно сделать таким:

```text
0x2C -> QMC5883P
0x0D -> QMC5883L
0x1E -> HMC5883L
```

То есть в `detectMagnetometer()` добавить вызов `detectQmcP()`, не удаляя существующие драйверы.

Сообщение об отсутствии датчика также обновить, например:

```text
No supported magnetometer initialized (QMCP=0x2C, QMC=0x0D, HMC=0x1E); SDA=16 SCL=17
```

## printMagnetometer()

Добавить обработку нового флага до старых вариантов:

```cpp
if (qmcPReady) {
    printQmcP();
    return;
}
```

После этого оставить существующие QMC5883L и HMC5883L без изменений.

## compassTick()

Это важное место. Сейчас `compassTick()` выбирает только между QMC5883L и HMC5883L:

```cpp
const uint8_t address = qmcReady ? QMC_ADDRESS : HMC_ADDRESS;
```

Для `0x2C` необходимо добавить третью ветку и использовать:

- адрес `0x2C`;
- status-регистр QMC5883P;
- начало блока XYZ QMC5883P;
- правильную проверку готовности данных;
- правильный порядок X/Y/Z.

Иначе диагностика может видеть магнитометр, а экран компаса останется без курса.

## Что НЕ нужно менять

Подключение остаётся прежним:

```text
ESP32       магнитометр
GPIO16  ->  SDA
GPIO17  ->  SCL
3.3V    ->  VCC (если модуль рассчитан на 3.3 В)
GND     ->  GND
```

Основная I2C-шина GPIO21/GPIO22 не используется для магнитометра.

## Проверка после прошивки

В Serial Monitor сначала проверить I2C scan. На второй шине ожидается:

```text
I2C scan magnetometer SDA=16 SCL=17:
  0x2C
```

Затем должны появиться сообщения об успешном определении QMC5883P и изменяющиеся значения X/Y/Z при вращении платы.

После этого проверить страницу компаса. Курс должен изменяться плавно при вращении устройства.

## Важно

Сам факт ACK на `0x2C` подтверждает наличие I2C-устройства по этому адресу, но не является достаточной идентификацией конкретной микросхемы. Поэтому драйвер `0x2C` должен проверять устройство перед записью конфигурации, а не только полагаться на адрес.
