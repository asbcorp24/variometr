# Полётный журнал, схема 1

Хранилище — LittleFS в разделе `flight_ext` внешней SPI NOR 32 МиБ
(MX25L25645G, JEDEC C22019, или W25Q256 3 В, EF4019). Внутренняя flash
не используется для новых логов; старые записи не удаляются и не переносятся. Приложение выгрузки пока
не реализовано. Имена файлов: `/f00000001.csv`, `/f00000002.csv` и т. д. Идентификаторы
не используются повторно при обнаружении файлов с повреждённым заголовком.

## Обрамление строки

Каждая строка — ASCII, числа с десятичной точкой:

```text
payload*CRC32\n
```

После `*` ровно восемь шестнадцатеричных цифр. CRC32/IEEE вычисляется по байтам
`payload`, без `*`, контрольной суммы и перевода строки. Начальное значение
0xFFFFFFFF, отражённый полином 0xEDB88320, финальный XOR 0xFFFFFFFF.
Контрольный вектор: CRC32(`123456789`) = 0xCBF43926.

## Виды строк

| Метка | Поля payload после метки |
|---|---|
| `H` | `schema,id,start_utc,zone_minutes,clock_trusted,qnh_hpa,start_altitude_m` |
| `S` | `elapsed_ms,altitude_m,vertical_speed_mps,pressure_pa,battery_voltage_v` |
| `G` | `elapsed_ms` — пропуск достоверного барометрического измерения |
| `C` | `elapsed_ms,max_altitude_m,max_gain_m,max_climb_mps,min_climb_mps,samples,gaps,end_reason` |
| `E` | Те же поля, что у `C`; окончательная сводка и причина завершения |

Значения `schema=1`, `clock_trusted=0/1`. При недостоверных часах `start_utc=0`,
дата помечается неизвестной. `zone_minutes` — смещение от UTC в начале записи.
После настройки часов RTC и `start_utc` хранят UTC, в интерфейсе дата конвертируется
в текущий выбранный пояс. Длительность не зависит от перевода часов.

`altitude_m` — барометрическая высота по зафиксированному QNH.
`max_gain_m` — максимальное превышение над высотой старта, минимум 0.
`max_climb_mps` — максимум положительной вертикальной скорости, минимум 0.
`min_climb_mps` — минимум вертикальной скорости, максимум 0; модуль этого числа
показывает наибольшее снижение. Это не горизонтальная или путевая скорость.
Если напряжение неизвестно, в `S` сохраняется `-1.000`.

`samples` и `gaps` в сводке — счётчики обработанных барометрических измерений,
а не число строк `S`. Максимумы собираются на этих измерениях; `S` пишется раз
в секунду. Поэтому сводка может содержать максимум, которого нет в точках `S`.

## Причина завершения

| Код | Значение |
|---|---|
| 0 | Активная запись; допустим только в `C`, не в `E` |
| 1 | Ручное завершение через меню |
| 2 | Незавершённая запись / обрыв питания — выставляется при восстановлении без `E` |
| 3 | Недостаток места |
| 4 | Ошибка записи |

При ошибке flash финальная `E` также может не сохраниться. В этом случае после
перезапуска запись будет незавершённой, даже если в RAM перед выключением была
зафиксирована причина 4. Это предпочтительнее ложного признака успешного завершения.

## Восстановление и ограничения

Заголовок обязателен. Частичная последняя строка, неверная CRC, неверный формат,
недопустимые числа и строки с уменьшившимся `elapsed_ms` не принимаются.
После корректной `E` дальнейшие строки не меняют статистику.
При отсутствии `E` используются последние целые строки и контрольные сводки,
показывается «ОБРЫВ ПИТАНИЯ / НЕ ЗАВЕРШЁН».

Контрольная сводка и `flush()` выполняются раз в 5 секунд; при штатном завершении —
сразу. Внезапное отключение питания может потерять хвост или повредить файловую
систему; программная проверка не заменяет резерв питания и испытания на плате.

Лимит — 64 читаемые записи и доступная flash. Для старта требуется 64 КиБ свободно;
при остатке менее 16 КиБ запись завершается, резерв оставлен для сводки. Старые
файлы не удаляются автоматически. При неудачном монтировании форматируется только
полностью стёртый раздел (все байты 0xFF), существующие данные не стираются.

Очистка через меню удаляет все файлы вида `/fXXXXXXXX.csv` (ровно 8 цифр),
включая повреждённые. Нужны подтверждение ДА и остановленная запись.
Посторонние файлы сохраняются, чип не форматируется. При частичном удалении
перечитывается список оставшихся полётов; очистку можно повторить. После полной
очистки нумерация начинается с 1.

Экспорт в приложение пока не реализован. Для будущей выгрузки следует сохранять
исходные файлы и проверять CRC до интерпретации данных. Распиновка внешней памяти
и проверка адресации выше 16 МиБ описаны в README.
